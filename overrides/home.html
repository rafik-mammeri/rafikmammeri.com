How I work

{% include ".icons/lucide/route.svg" %} Architecture before prompts

The biggest latency and cost wins in LLM systems are structural. The assistant answers in one or two model calls per message not because of clever prompting, but because routing and handoffs are native to the graph.

Proof: the swarm design at Boulanger · the article

{% include ".icons/lucide/shield-check.svg" %} Governance before scale

I learned model governance under banking regulators, and I run AI the same way: assume the model will be wrong. Critical decisions stay in code, an agent can only read the data its use case is scoped to, and production rights are earned, not given.

Proof: Self-BI's four-layer model · regulated-banking roots

{% include ".icons/lucide/users.svg" %} The business owns the product

The HR assistant is owned by HR: content, scope, response validation. My job is making sure the technical layer never gives them a reason to doubt it.

Proof: the HR product-owner model

{% include ".icons/lucide/refresh-cw.svg" %} Production is a loop, not a launch

Versioned prompts, LLM-judge scoring against live traffic, and continuous releases since day one. On the voice line, the first day of production led to five fixes in 48 hours. Quality is maintained, not achieved once.

Proof: the quality loop at Boulanger
